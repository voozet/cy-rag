---
title: SQL Injection
source: OWASP
url: https://owasp.org/www-community/attacks/SQL_Injection
section: Injection
---
OWASP describes SQL injection as an attack technique in which an attacker supplies untrusted input that is incorporated into a SQL query in a way that alters the query's intended logic, potentially allowing the attacker to read or modify data they should not have access to, bypass authentication, or in some cases execute administrative operations on the database. SQL injection is possible whenever application code builds a query by directly concatenating user-supplied input into a SQL statement rather than treating that input strictly as data. OWASP's primary recommended defense is the use of parameterized queries (also called prepared statements), in which the SQL command structure is defined separately from the data values, so that user input can never change the meaning of the query regardless of its content. A related defense is the use of safe, vetted database APIs or Object-Relational Mapping (ORM) frameworks that construct queries safely by default. Where dynamic query construction cannot be fully avoided, OWASP recommends strict input validation using allow-lists for expected formats (such as validating that an identifier matches an expected pattern) and proper escaping of any special characters using an escaping scheme specific to the target database engine, though OWASP notes that escaping alone is a weaker and more error-prone defense than parameterization. OWASP also recommends applying the principle of least privilege to database accounts used by applications, so that even if injection occurs, the account's permissions limit the actions an attacker can take, for example by avoiding use of database administrator accounts for routine application queries and disabling unnecessary database functionality such as stored procedures that are not required. Additional defense-in-depth measures include using a web application firewall to help detect and block known injection patterns, and conducting regular code review and automated static or dynamic testing specifically targeted at identifying injection flaws before deployment.
